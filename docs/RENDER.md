# Deploy on Render

Local Compose stays on localhost. Render is a second place to run the same images. The public addresses are fixed by the service names in [render.yaml](../render.yaml):

| What | Local | Render |
|---|---|---|
| Application | http://localhost:4200 | https://adfinance-rwanda-cates-web.onrender.com |
| API | http://localhost:8082 | https://adfinance-rwanda-cates-api.onrender.com |
| Keycloak | http://localhost:8081 | https://adfinance-rwanda-cates-auth.onrender.com |
| Postgres | localhost:5433 | private database `adfinance-rwanda-cates-db` |
| Redis | localhost:6379 | private Key Value `adfinance-rwanda-cates-redis` |

Do not delete the local URLs from the other documents. Add a Render change next to them.

## What the blueprint creates

- `adfinance-rwanda-cates-web` — Angular and nginx. The browser calls `/api/` on this host. nginx proxies to the API over the private network. The image writes `/config.json` with the Keycloak issuer at start, so the SPA is not baked to localhost.
- `adfinance-rwanda-cates-api` — the Spring Boot API. Flyway migrates and seeds on first boot. `PORT` is `10000`, which Render's proxy uses.
- `adfinance-rwanda-cates-worker` — the same image with profile `worker`.
- `adfinance-rwanda-cates-auth` — Keycloak with the realm file and the Taskflow theme. It listens on `10000` behind Render's HTTPS proxy. The token issuer is `https://adfinance-rwanda-cates-auth.onrender.com/realms/taskflow`.
- `adfinance-rwanda-cates-db` — Postgres 16. The API entrypoint turns Render's `DATABASE_URL` into a JDBC URL.
- `adfinance-rwanda-cates-redis` — Key Value. The API reads `REDIS_URL`, including `rediss://` when TLS is required.

The web app, the API, Postgres, and Redis use the free plan. Keycloak and the worker use `starter`. Keycloak does not stay up in a 512 MB free instance, and Render does not offer a free background worker. Expect about two starter instances. The free database expires; Render shows the date in the dashboard.

Demo users and the password `password` come from `keycloak/realm-export.json`. The Keycloak admin password is generated by Render and is not in git. `.env` is not used on Render and must stay uncommitted.

## Steps

1. Confirm `main` on GitHub contains `render.yaml`: https://github.com/ADFinance-Rwanda/Cates
2. Sign in to Render and connect the GitHub account that can read that repository.
3. Open **New** → **Blueprint**.
4. Select `ADFinance-Rwanda/Cates` and branch `main`.
5. Render reads `render.yaml`. Apply it. The first screen can ask you to confirm the generated Keycloak admin password. Let Render generate it.
6. Wait until the web, API, and Keycloak services are live. The first API boot runs Flyway. Keycloak imports the realm once.
7. Open https://adfinance-rwanda-cates-web.onrender.com and sign in as `alice` / `password`.

Free web services sleep after a period with no traffic. The first request after sleep can take a minute, and Keycloak must be awake before sign-in succeeds. If sign-in reports that the provider is unreachable, open the Keycloak URL once, wait for the realm page, and try again.

## If a name is already taken

Render hostnames are global. If a service name is rejected, change that name in `render.yaml` and the matching redirect URI in `keycloak/realm-export.json`, then sync the blueprint. The SPA, the API issuer, and Keycloak's `KC_HOSTNAME` must stay the same string.

## What stays local

`docker compose up --build` still binds `127.0.0.1:4200`, `127.0.0.1:8082`, and `127.0.0.1:8081`. Backup and restore scripts still talk to the Compose Postgres. They are not pointed at Render.
